# Security & Privacy

Personal Doctor AI is a **local, single-machine** application. This document describes its protections and
their limits. It has **not** undergone an independent security audit, and no HIPAA, GDPR, APPI or other
regulatory compliance is claimed.

## Authentication & sessions
- Passwords hashed with **Argon2id** (`argon2-cffi` defaults); constant-time-ish login (dummy hash for unknown emails).
- Password policy: ≥ 10 characters with letters and digits.
- Session: HS256 **JWT in an HttpOnly, SameSite=Strict cookie** (`pdai_session`), 12-hour lifetime
  (`ACCESS_TOKEN_MINUTES`). `Secure` is set when `APP_ENV=production` (HTTPS).
- **CSRF**: double-submit cookie (`pdai_csrf` + `X-CSRF-Token` header) enforced by middleware for every
  unsafe request carrying a session; SameSite=Strict provides a second layer.
- No tokens or secrets are stored in `localStorage`/`sessionStorage` (only the theme preference).

## Authorization & data isolation
- Every private resource is read/updated/deleted through `OwnedRepository.get_owned`, which filters on both
  the record id **and** the authenticated user id. Other users' ids return **404** (no existence leak).
- Identifiers are random UUIDs.
- AI context is built only from the requesting user's rows. Tests cover isolation for every resource,
  documents, conversations and AI context.

## OpenAI API keys
- Sent once from the browser over the local connection; never returned by any endpoint (only `sk-…last4`).
- **Encrypted at rest with Fernet** (AES-128-CBC + HMAC-SHA256). The master key (`ENCRYPTION_KEY`) lives in
  `backend/.env` (mode 600), outside SQLite, generated by `setup.command`. `.env` is git-ignored.
- Decrypted in memory only for the duration of a request; never logged (error handlers log exception types only).
- Users can remove their key at any time.

## Consent & data sent to OpenAI
- Nothing is sent without the **"Allow sending my chat messages to OpenAI"** consent.
- Saved health information is included only with a separate switch **and** the per-conversation toggle, and
  only relevant items are selected (see ARCHITECTURE.md).
- Documents: requires the "Allow document analysis" switch **plus** an explicit per-document consent checkbox.
  Only extracted text is sent — never the PDF file.
- Requests use `store=False`. OpenAI's own data-usage policies apply to API traffic.

## Uploads
- PDF only: extension, MIME type and `%PDF-` magic bytes checked; size limit (`MAX_UPLOAD_MB`, default 15).
- Stored as `<uuid>.pdf` under `backend/data/uploads/<user-id>/`; original names are sanitised for display only.
- Resolved paths are verified to stay inside the upload directory (path-traversal protection). Absolute paths
  are never returned by the API.
- Files are deleted with their record and on account deletion.

## Network & transport
- Backend binds to `127.0.0.1`, Vite to `localhost` — not exposed to the network.
- CORS restricted to the configured frontend origin; the SPA uses a same-origin proxy.
- Security headers: `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`,
  `Cache-Control: no-store` on API responses.

## Abuse protection
- In-memory sliding-window rate limits: auth endpoints per IP (`AUTH_RATE_LIMIT_PER_MIN`, default 10/min),
  AI endpoints per user (`AI_RATE_LIMIT_PER_MIN`, default 20/min).

## Logging & audit
- `audit_logs` records actions (login, uploads, AI use, exports, deletions…) with resource ids only — never
  message content, health values or secrets. Uvicorn access logs are disabled by the launcher.

## User rights
- **Export** everything as JSON (Settings → Data management).
- **Delete account** removes all rows (cascade) and uploaded files after password + "DELETE" confirmation.

## Medical safety
- Version-controlled system prompt (`backend/app/prompts/system_prompt_v1.md`): no diagnosis, no prescribing,
  no fabricated values, explicit uncertainty, no risk scores.
- Rule-based urgent-symptom detection runs **before** any AI call and works without an API key. It is a
  conservative safety net with known limits (keyword-based; can miss phrasing or over-trigger).

## Known limitations
- Local data at rest (SQLite, PDFs) is protected by macOS account security / FileVault, not app-level encryption.
- The rate limiter is in-memory (resets on restart) — adequate for a single local user.
- Anyone with access to your macOS account can read `backend/.env` and the database.
- Development server (Vite) is used for the local UI; a production deployment would need HTTPS, a production
  build served by a hardened web server, secret management and a security review.

## Reporting
For a local MVP, report issues to the project maintainer. Never include real health data in bug reports.
